## Why

Two capability specs say a secret is "stored as a reference". The User Book
says the opposite, and the code follows the User Book.

- `identity/auth-providers` says a provider is enabled "by supplying client
  identifiers and secret references" and that "Secrets MUST be stored as
  references". The User Book says a `clientSecret` "is a value, not a
  reference": the control plane seals it under a key bound to the project,
  environment and provider name, neither plane returns it, and a provider
  saved without a secret keeps the installed one.
- `sync/database-webhooks` says an endpoint has "a signing secret stored as a
  reference and shown once". The User Book says the platform generates the
  secret, stores it sealed, shows it exactly once, and replaces it only by
  rotation. The same requirement lets a delivery carry document fields "the
  endpoint's policy scope" allows; the User Book says document fields are
  never included.

A reference (`env:NAME` or `file:/path`) is the rule for deployment
configuration. A developer cannot hand the platform a reference into the
platform's own environment, so these two tenant-supplied or tenant-facing
secrets were never references.

## What Changes

- `identity/auth-providers`: the requirement "External sign-in providers" says
  a client secret is a value that is sealed before storage, bound to the
  project, environment and provider name, never returned, kept when a
  replacement omits it, and required when none is installed. Two scenarios are
  added for that behaviour.
- `sync/database-webhooks`: the requirement "Webhook endpoints on collection
  changes" says the signing secret is generated by the platform, stored sealed,
  shown once and replaced only by rotation, and that a delivery never carries
  document fields. One scenario is added for rotation.
- `docs/requirements-traceability.md` gains a row for each new scenario and
  renumbers the rows after them.

No code changes: the implementation already behaves this way, and existing
tests cover each new scenario.
