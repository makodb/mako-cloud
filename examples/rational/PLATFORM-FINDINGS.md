# Platform findings from Rational

Every platform defect or gap that Rational exposes is recorded here as it is
found: the symptom, the platform change that fixes it (with its commit once
landed), and the regression test that guards it. A finding is closed when the
suite that exposed it passes against the fixed platform; a finding the plan
defers is marked deferred with the reason.

| # | Found by | Symptom | Platform change | Regression test | Status |

| 1 | Task 1.2 — validating the household policy form | The policy language parses dotted paths only (`claims.a.b`); a rule cannot look up a trusted claim keyed by a document field, so `claims.households[new.household_id]` does not compile and app-managed sharing cannot be expressed. | Index expressions on trusted claims: `claims.<path>[<expression>]` with string or number index, `null` for a missing member, `Dynamic` result, only `claims.*` indexable. | `crates/mako-policy/src/evaluator.rs` household-role index tests and `document_hook.rs` end-to-end (editor creates in its household, viewer and stranger denied) | fixed — index expressions `claims.<path>[<expr>]`, diagnostics `index_not_allowed`/`index_type_invalid`, documented in `docs/document-policies.md` |
| 2 | Task 1.3 — storage client | `PUT …/storage/{bucket}/objects/{path}` ignores `If-None-Match`, so an application cannot make an upload create-only; two devices attaching a receipt at the same path silently overwrite each other. | `handle_put` parses `If-None-Match: *`, `If-Match: *`, and `If-Match: "<etag>"`; a malformed or unsupported precondition is refused rather than ignored; failure is `412 precondition_failed`. | `crates/mako-smoke/tests/file_storage.rs` conditional-upload cases | fixed |
| 3 | Task 1.1 — opening the model | RxDB's open-source build refuses more than 13 open collections per page (`COL23`); the 2 directory + 13 household collections of design decision 3 cannot all be open. | Not a platform defect — a design adjustment: fold `categories`+`tags` into `taxonomy`, `alert_settings`+`alerts` into `alerts`, `import_batches`+`institution_connections` into `connections` (kind fields), leaving 10 household + 2 directory collections. | Rational live suite opens every collection | design change (decision 3 addendum) |
| 4 | Task 1.9 — live replication | One SSE stream per collection: 12+ streams exhaust a browser's six HTTP/1.1 connections to one host (Vite proxy, any HTTP/1.1 front), starving pulls and pushes; Rational streams two collections and polls the rest. | An environment-scoped live stream serving several collections over one connection (`…/replication/stream?collections=a,b,…`, events tagged with the collection) and client support in `MakoLivePullStream`. | mako-sync multi-collection stream test; Rational live suite with every collection streamed | open |
| 5 | Task 1.9 — per-household databases | Pull returns every document the user may read across all households; a per-household database must filter client-side and re-scan other households' changes, and a full page of foreign documents stalls RxDB's checkpoint advance without the handler's own paging loop. | A pull/stream filter on an indexed equality (`filter: {field, value}`) applied after policy, with the checkpoint bound to the filter. | mako-sync filtered pull test; Rational live suite | open |
| 6 | Task 1.9 — session refresh | `MakoAuthClient.refreshSession` is not coalesced and clears the persisted session on any failure: two scopes refreshing on one epoch signal consume the rotated refresh token twice (401 → signed out), and an offline restart with an expired access token signs the user out. | Coalesce concurrent refreshes in the client; keep the session on network failure and report `refreshUnavailable`; clear only on a definitive refusal. Pull, push, and storage now raise a retryable `unavailable` instead of signing out, and the live stream reconnects. | `packages/rxdb-client/test/refresh.test.mjs` (coalescing, 503/429 keep the session, 401 clears it, offline restart) and `test/pull.test.mjs` | fixed |
| 7 | Task 1.1 — bootstrap through the service document route | (a) Reusing an `X-Mako-Request-Id` across two service requests surfaces as `503 unavailable "quota authority is unavailable"` with retry advice — it is a reservation conflict keyed by request id; (b) `Idempotency-Key` must equal the body `mutationId` (409) and nothing documents it; (c) `{documentId}` is compared byte-for-byte with the body id without percent-decoding, so an id containing `:` sent encoded is refused as a path mismatch. | Request-id reuse is now `409 conflict` naming the header instead of `503 unavailable`; the id is percent-decoded; `docs/api.md` documents both and the `Idempotency-Key == mutationId` rule. | the edge smoke asserts the `409` | fixed |
| 8 | Task 1.1 — receipts bucket rules | Bucket rules see the object document (`path`, `owner_id`, …) but nothing that names the household, so a receipt cannot be readable by household members — only by its uploader. | Objects accept attributes at PUT (`X-Mako-Object-Attributes`, ≤8 string pairs, stored on the object document as `attributes`) that rules can read: `claims.households[new.attributes.household_id] != null` verifies membership against the claim, so a false attribute grants nothing. | file-storage smoke: member reads, outsider refused | open |
| 9 | Reviewing the deployment plan — "the sample must be built like any user's project" | A project's ordinary API URL is on the platform hostname, and the platform hostname was designed never to emit CORS: a browser application hosted anywhere (a static host, a laptop, a teammate's machine) could not call its own project's API. The only escape was a custom domain, so every browser app would need a DNS name it owns before it could talk to the platform at all. | The origin allowlist belongs to the environment, not to a custom domain: `GET`/`PUT …/environments/{e}/allowed-origins`, installed into the data plane like the quota policy, honored on the environment's application routes on the platform hostname and on any custom domain; management, operator, and service routes never answer cross-origin. | `crates/mako-smoke/tests/custom_domains.rs` (platform hostname and custom domain, unlisted origin, management route unlabelled, cleared list) | fixed |
| 10 | Task 1.7 — deploying the households function | **A deployed function cannot import `@mako-cloud/edge-sdk`.** The bundle validator and the supervisor pass the bare specifier through, and Deno then refuses it in the user worker (`Relative import path "@mako-cloud/edge-sdk" not prefixed with / or ./ or ../`), so the deployment is never promoted and `functions deployments create` answers `503`. The pattern `docs/edge-functions.md` documents is unimplementable, and nothing caught it because the only function the platform ever deploys imports nothing. | Supply the module to the worker: an import map in the deployment (or vendoring the SDK into the bundle at upload), with the validator resolving it and the runtime honoring it. | `crates/mako-smoke/tests/edge_function.rs` deploys a `budget` function that imports the SDK, holds a service credential as a supplied secret, and writes `hh_local:groceries:2026-08`; reverting any one of the three fixes fails it | fixed — the SDK travels in the main worker's module graph and is mapped per user worker by an inline import map; the validator accepts that one specifier deliberately and now refuses reserved paths and remapping |
| 11 | Task 1.7 — giving the function its credential | A service credential cannot be handed to a function: `createFunctionSecret` and `createServiceCredential` each generate their own value and neither accepts one, so the documented `SERVICE_KEY`-as-a-secret pattern cannot be built. Rational writes the credential into the uploaded copy of the bundle, which is a secret at rest in a stored artifact. | `PUT …/function-secrets/{name}` (`createFunctionSecretValue`) accepts a supplied value and answers with metadata only; `mako functions secrets create --value/--value-file`; write-once, never returned, redacted. | the same edge smoke, plus management assertions that the value is never disclosed and a repeat is `409` | fixed |
| 12 | Task 1.7 — writing membership documents | The edge SDK percent-encodes `{documentId}` while the data-plane route compares raw bytes (finding #7c, worse than recorded): **no** function can write a document whose id contains `:`, `@`, or anything `encodeURIComponent` escapes. Rational's membership ids became `<household>.<user>`; the planned budget ids `<household>:<category>:<month>` would be unwritable from a function. | The data plane percent-decodes the path id before parsing, on caller-scoped and service routes alike, and refuses a malformed escape. | the edge smoke writes an id containing `:`; reverting just this change reproduces the original error | fixed |
| 13 | Task 1.7 — scoping an invitation | A policy cannot match a document field against the caller's verified email: `identity` exposes only `user_id` and `role`. A pending invitation cannot be scoped to its invitee, so Rational lets any signed-in user read `status == "invited"` rows and filters on the device — which discloses invited addresses environment-wide. | Expose the verified email (and other verified identity attributes) to policies as `identity.email`, so `old.email == identity.email` scopes an invitation. | policy compiler/evaluator test; Rational's memberships policy tightened | open |
| 14 | Task 1.7 — changing a role | `setAppMetadata` replaces the `households` claim whole, and a function cannot read another user's app metadata, so every role change must rebuild the claim from the app's own projection (and needed a `(user_id, updated_at)` index to do it). | A nested merge on app metadata, or a service-side read of a user's trusted metadata. | edge-SDK/data-plane test for a nested patch | open |
| 15 | Task 1.7 — local function deployment | Deploying a function needs a real S3 object store, but `mako-local-bootstrap` uses an in-memory one and `docs/local-functions.md` does not say so; the compose object store also starts with no S3 identity and refuses the platform's signed requests (`InvalidAccessKeyId … Available keys: 0`). | `docs/local-functions.md` and the smoke header now state that the bootstrap deploys in process with an in-memory store, while the CLI and management API need a credentialed S3 store or answer `503`. | the edge smoke's setup | fixed (documented) |
| 16 | Task 1.7 — replication coordinators | Two client sharp edges: `MakoAuthorizationEpochCoordinator.initialize()` clears through `clearReplicatedCollection` before any session exists, so an app that merely closes a database keeps the previous generation's data after a restart; and a stream `authorization_epoch_changed` racing the app's own post-write epoch sync produces two concurrent resets of one scope (surfaced as RxDB `DB8`). | Clear by database identity rather than through an open handle, and serialize resets per scope inside the coordinator. | `packages/rxdb-client` coordinator tests | open |
| 17 | Exporting the app — a reload of the published demo | A `401 unauthenticated` on `…/replication/pull` reaches the app as `internal: replication operation failed`, and the app retries it forever: the response carries `retry: {kind: "never"}`, `MakoReplicationError` still classifies it as `internal`/retryable, and the pull loop spins (hundreds of requests a minute, one per collection). A person whose session ends mid-visit sees a client that looks connected, never syncs, and never asks them to sign in again. Found because a reload of the sample's in-browser fake retired its sessions; a real environment reaches the same state whenever a session is revoked or expires while the tab is open. | A `401`, and any envelope advising `never`, is now classified non-retryable `unauthenticated` at the one classification point; the client renews once through the coalesced refresh and repeats the request once, then stops; `after_delay` advice carries its delay through; the error RxDB flattens is unwrapped so signals and recovery finally see the real code | `packages/rxdb-client/test/` — nine cases asserting exact request counts (401→renew→success is 2 pulls + 1 token; a second refusal is bounded, not unbounded), push and live-stream equivalents, `retry: never` on a 500, and the `RC_PULL` unwrap | fixed |
| 18 | Fixing #10 — reading the worker's permissions | **Customer functions were not sandboxed as claimed.** `packages/cli/runtime/main/supervisor.ts` started each user worker with `allow_net/write/run/ffi/sys/import: []`; in Deno an empty list is *granted without restriction*, so only `allow_read` and `allow_env` were real restrictions, and `mako functions serve` passed no `permissions` object at all (granting everything). Measured against the pinned runtime, the genuine escapes were **network to any host and port** (including raw `Deno.connect` sockets and WebSockets), **remote module import**, and **filesystem writes** — a deployed tenant function reached the *control plane* on loopback with status 200 and wrote the container filesystem. (My original claim that `run` and `ffi` were reachable was wrong: this image blocks subprocesses unconditionally and exposes no FFI to user workers. `sys` was granted but answers sanitized constants.) Meanwhile the manifest asserted `outboundNetwork: {mode: "deny_all"}` and the protocol doc promised `deny_all` or a bounded allowlist, and a unit test **pinned the defect in place** by asserting `allow_net: []`. | Deny by default with `null` per capability and `allow_all: false` (verified empirically: `null` yields Deno's `NotCapable`, `[]` yields no error at all), in both the deployed and the local `serve` path. `outboundNetwork: deny_all` now resolves to exactly one `allow_net` entry — the platform API origin's `host:port`, port explicit so granting the API host does not grant its neighbours — so the injected SDK still works while the function's own destinations are denied. `write`, `import`, `run`, `ffi`, and `sys` withheld outright, so a future image that exposes more surface does not silently widen the sandbox. | `crates/mako-smoke/tests/edge_function.rs` deploys a `sandbox` function and asserts Deno `NotCapable` for a foreign-host fetch, a raw socket, an out-of-directory write, reading supervisor state, and an ungranted environment variable — with the 'foreign' origin being the control plane on the neighbouring port, genuinely listening, so a refusal is a denial and not an unreachable address — while the SDK's platform call still returns 200. Reverting the permissions fails it; the `serve` unit test now forbids `allow_*: []`. | fixed |
| 19 | Running the workspace gate chain after a day's work | **The smoke suite silently tested stale binaries.** `binary_directory()` read `<workspace>/target/debug` unless `MAKO_SMOKE_BINARY_DIR` was set, but `cargo test --workspace --tests` under a custom `CARGO_TARGET_DIR` builds test binaries there and leaves the workspace target untouched — so the suite launched service binaries a day older than the sources under test, and reported the mismatch as a readiness timeout in a service whose code was fine. A green integration run proved nothing about the code that had just been written. | `binary_directory()` honours `CARGO_TARGET_DIR`, and `start_service` refuses to launch a binary older than the newest `.rs` under `crates/` or `services/`, naming the file that is newer and how to rebuild. | the guard itself: the run that exposed this now fails immediately with the rebuild instruction instead of timing out 30 s later | fixed |
